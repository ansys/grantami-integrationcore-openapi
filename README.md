## Project overview

Use this autogenerated client library to access the Granta MI Integration Services. The repository
contains OpenAPI definitions for two related APIs and generates them into a single Python package
with separate submodules:

- **Material Model Service** (`material_models`): Access material model definitions, export, and search.
- **Integration Service** (`integration`): Access sessions for the Granta Material Picker and related
  integration workflows.

Make commits to this repository only when you update the OpenAPI YAML definitions
in the `yaml/` directory. The generation process updates the Python code automatically when you
modify the YAML definitions.


## Contributing

This repository is not under active development beyond API definition updates. It stores code
generated from the API definitions. Develop application-level features in consuming projects that
depend on this package.


## Releasing

This package follows [Semantic Versioning](https://semver.org/). Release candidates are versioned
as `MAJOR.MINOR.0rc<ITERATION>`.

The process follows the standard PyAnsys [Releasing and publishing guidelines](https://dev.docs.pyansys.com/how-to/releasing.html).

1. Check that the `main` branch build status is green, which indicates that the most recent run of the CI workflow was successful.
2. Create a branch named `release/MAJOR.MINOR` from the `main` branch and push it to GitHub.
3. Generate a *release* `pyproject.toml` file by completing one of these options:
  * Change the version number in the `<version>` XML element in the `pom.xml` file and open a pull request.
  * If the version number is correct, create a branch from the release branch, manually run the `Generate client library` GitHub action, and open a pull request.
4. Pull the branch and confirm that the latest commit includes the *release* `pyproject.toml` file.
5. Tag the release:
   ```console
   git tag v<MAJOR.MINOR.0rc0>
   git push origin --tags
   ```

After you push the tag to GitHub, a workflow builds and publishes the release.

## Using this package

The `ansys-grantami-integrationcore-openapi` package provides low-level bindings for the
Integration Services APIs. Each API is exposed as a separate submodule within the same installable
package.

### Requirements

The `ansys-grantami-integrationcore-openapi` package requires Granta MI 2027 R1 or later.

### Installation

During active development, this repository stays up to date with new versions of the API
documentation. To use the latest version of this package in another project, add a dependency on
the repository's `main` branch. Use `uv` or `pip` as shown in the following examples.

Use uv:

```console
uv add git+https://github.com/ansys-internal/grantami-integrationcore-openapi#subdirectory=ansys-grantami-integrationcore-openapi
```

Use pip:

```console
pip install git+https://github.com/ansys-internal/grantami-integrationcore-openapi.git#subdirectory=ansys-grantami-integrationcore-openapi
```

### Package structure

Both APIs share the top-level import path `ansys.grantami.integrationcore_openapi` but are
generated into separate submodules:

| Submodule | OpenAPI definition | Purpose |
|-----------|-------------------|---------|
| `material_models` | `yaml/material_model_service.yml` | Material Model Service REST API |
| `integration` | `yaml/integration_service.yml` | Integration Service REST API |

Import API classes and models from the submodule that matches the service you are calling:

```python
from ansys.grantami.integrationcore_openapi.material_models import api as mms_api
from ansys.grantami.integrationcore_openapi.material_models import models as mms_models
from ansys.grantami.integrationcore_openapi.integration import api as integration_api
from ansys.grantami.integrationcore_openapi.integration import models as integration_models
```

Each service has its own base URL. Create a separate `ApiClient` for each service and call
`setup_client()` with that service's models module before invoking its API classes.

### Minimal setup

The following example shows how to authenticate and call each API. Update the URLs and
authentication method for your environment.

```python
from importlib.metadata import version

from ansys.openapi.common import ApiClient, ApiClientFactory, generate_user_agent
from ansys.grantami.integrationcore_openapi.material_models import api as mms_api
from ansys.grantami.integrationcore_openapi.material_models import models as mms_models
from ansys.grantami.integrationcore_openapi.integration import api as integration_api
from ansys.grantami.integrationcore_openapi.integration import models as integration_models
from ansys.grantami.integrationcore_openapi.integration.models import SessionRequest, SessionSettings

PACKAGE_NAME = "ansys-grantami-integrationcore-openapi"
GRANTA_APPLICATION_NAME_HEADER = "PyGranta Integration Core"

MMS_API_URL = "https://my-server/material-model-service"
INTEGRATION_API_URL = "https://my-server/integration-service/api/v1"


def create_client(api_url: str) -> ApiClient:
  ver = version(PACKAGE_NAME)
  client = (
    ApiClientFactory(api_url)
    .with_autologon()  # Replace with .with_oidc(...) or another supported auth method
    .authorize()
    .connect()
  )
  client.configuration.headers["X-Granta-ApplicationName"] = GRANTA_APPLICATION_NAME_HEADER
  client.configuration.headers["User-Agent"] = generate_user_agent(PACKAGE_NAME, ver)
  return client


if __name__ == "__main__":
  # Material Model Service
  mms_client = create_client(MMS_API_URL)
  mms_client.setup_client(mms_models)

  databases_api = mms_api.DatabasesApi(mms_client)
  databases = databases_api.v1_databases_get()
  print(databases)

  # Integration Service
  integration_client = create_client(INTEGRATION_API_URL)
  integration_client.setup_client(integration_models)

  sessions_api = integration_api.DefaultApi(integration_client)
  session = sessions_api.sessions_post(
    body=SessionRequest(
      name="my-session",
      settings=SessionSettings(title="My session", package_name="Mechanical"),
    )
  )
  print(session)
```
